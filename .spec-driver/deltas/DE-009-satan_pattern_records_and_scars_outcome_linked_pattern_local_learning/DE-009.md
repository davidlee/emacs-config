## 1. Summary & Context

- **Technical Spec(s)**: none — project is delta-first, no tech-spec artefacts on disk.
- **Implementation Plan**: [IP-009](./IP-009.md) – not yet planned (DR pending).
- **Change Drivers**: intake note `20260519T003129` (SATAN vision §3/§7); design note `patterns_attributes`; gap analysis in `docs/satan/epistemics-roadmap.md`.

## 2. Motivation

SATAN's outcome observer already classifies matured interventions (worked / ignored
/ neutral / contradicted / harmful) and the attribute-listener turns those verdicts
into **global** attribute deltas (Shame, Doubt, Brooding, …). That is the *metabolism*
half of learning. The *epistemic* half is unbuilt: nothing accrues against the
recurring context-shape that the intervention acted on.

The `patterns_attributes` design note mandates that each outcome update **both** global
attributes **and** the implicated pattern record. Only the global half exists, so:

- no `pattern.contradicted_count` / scars accrue → no pattern-local learning;
- no per-pattern cooldown or intrusion ceiling can form;
- "scar when wrong" (vision §16) has no substrate.

This delta builds the missing half. It is the cheapest, highest-leverage step
(extends an existing mechanism rather than greenfield) and is a prerequisite for the
later probe and hypothesis layers (epistemics-roadmap steps 2–3).

## 3. Scope & Objectives

- **Primary Outcomes**:
  - Persistent **pattern records** keyed by `cue_handles[]`, with the design-note
    shape: counters (`success/ignored/contradicted/harmful`), `last_seen/tested/outcome`,
    `scars[]`, `cooldown_until`, `intrusion_ceiling`, `default_intervention`,
    `enabled`, `priority`.
  - **Match** current-percept `cue_handles` → implicated pattern records.
  - **Outcome → pattern update**: each classified intervention outcome updates the
    implicated pattern(s) — bump the matching counter, append a scar on
    contradicted/harmful, stamp `last_outcome`/`last_tested_at`, adjust `cooldown_until`.
  - Pattern update is an **additive consumer** of the same audit-event stream the
    attribute-listener reads — not an inline edit of the global-attribute path.
- **Operational Constraints**: no regression to the existing global-attribute update;
  DB-backed (psql via `dl-satan-db`), schema migration alongside memory/attribute tables.
- **Dependencies**: none must land first; rides existing observer + audit-event plumbing.

## 4. Out of Scope

- **Action-gate enforcement** of `intrusion_ceiling` / `cooldown_until` — records and
  maintains the fields; the gate honouring them is a named follow-up (R2).
- **Auto-mining** patterns from recurrence/resonance — v1 is curated/explicit creation (R1).
- **Probe surface** and **hypothesis board** — roadmap steps 2–3, separate deltas.
- **Habitat rendering** of matched patterns/scars into the tank/capsule — follow-up.
- Module **extraction** (POL-001) — co-locate for v1; flag as candidate only.

## 5. Approach Overview

- **System Touchpoints**:
  - new `satan/dl-satan-pattern.el` — record store (CRUD, cue-handle match, scar append, counter/cooldown update);
  - new migration under `satan/memory/migrations/` — `satan_patterns` (+ scars) table;
  - new pattern-listener (mirror of `dl-satan-attribute-listener`) consuming the
    `intervention.outcome_classified` audit-event stream, OR extend the observer's
    classify path to also emit a pattern-update event — DR to choose;
  - `dl-satan-percept` / broker — supply matched pattern ids to the run (read path).
- **Key Changes**: pattern store + schema; cue-handle matcher; outcome→pattern updater.
- **Migration / Rollout Notes**: forward-only migration; empty store is a valid cold start.

## 6. Verification Strategy

- **Acceptance Criteria**:
  - A classified `contradicted`/`harmful` outcome on an intervention whose run percept
    carried handles matching pattern P bumps `P.contradicted_count`/`harmful_count` and
    appends a scar — verified by ERT against a seeded DB row.
  - A `worked` outcome bumps `success_count` and stamps `last_outcome=worked`.
  - Global-attribute update for the same outcome is unchanged (regression guard).
  - Cue-handle matcher returns the right pattern set for a given percept handle list.
- **Planned Artefacts**: ERT VT(s) for store + matcher + outcome-update; VA report on a
  live tick exercising the dual update. IDs assigned at plan time.

## 7. Follow-ups & Tracking

- **Future Phases / Deltas**: action-gate reads cooldown/intrusion ceiling; probe surface
  (roadmap step 2); hypothesis board (step 3); habitat rendering of patterns/scars.
- **Open Decisions / Questions** (for DR-009):
  - Pattern-creation source for v1 (curated seed file vs explicit tool) — R1.
  - New listener vs extend observer classify path — coupling trade-off (R3).
  - Scar payload shape (free prose vs structured evidence ref).
