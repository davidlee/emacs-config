# DR-010 – Decouple SATAN perception from agent run

## 1. Executive Summary

- **Delta**: [DE-010](./DE-010.md)
- **Status**: draft
- **Owners / Team**: David Lee
- **Last Updated**: 2026-06-09
- **Synopsis**: Cut the SATAN tick into **perceive** (deterministic, token-free,
  runs unconditionally before the budget gate) and **consume** (the gated LLM
  run that carries effects, interventions, and the consumption cursor). The cut
  also corrects a foundational flaw: perception today is *not* a pure function
  over the durable segment log — it fuses replayable segment series with
  non-replayable present-tense reads and a separate store (bough). This DR
  promotes the signal model so the percept reads (almost) only panopticon
  series, raising signal quality while cutting substrate count.

## 2. Problem & Constraints

### Current behaviour

A tick fuses deterministic context-prep with a token-spending LLM run that has
side effects. As built (not as `perceptual-design.md` §S1 narrates it), the
deterministic perception work runs *inside* `dl-satan-broker--spawn`
(`broker.el:695`), downstream of the budget gate:

```
broker-run → session gate → budget gate → --spawn
                                             observer-process        (DB writes)
                                             assemble-context        (percept/resonance/motive/sensor_status; persists percept.json)
                                             sensor-alerts-check      (fires notify)
                                             curiosity/content/wpm    (charge attributes)
                                             context-fn → bundle.json
                                             make-process (LLM)
```

Two concrete failures:

1. **ISSUE-001 — perception is budget-gated.** `broker-run` (`broker.el:687`)
   diverts budget-exceeded ticks to `--write-budget-denied-run`
   (`broker.el:622`), which writes a slim bundle and **never calls
   `assemble-context`**. Budget-denied ⇒ no percept. Sensing depends on whether
   the system can afford to think.
2. **Coarse invocation control.** The `satan-tick` systemd timer is disabled in
   favour of a waybar widget *because* a tick = prep + effects + tokens. There
   is no cheap "sample now" that does not also pay for and risk a full effecting
   run.

### The deeper flaw — perception is not a pure function over the segment log

ADR-001's decision text asserts perception is "a pure, deterministic function of
`segments[cursor..head]` over the already-durable panopticon segment log." This
is **aspirational, not true today.** The evidence assembler
(`dl-satan-memory-evidence-assemble`) is a fan-in over three substrates with
three different sequencing keys:

- **Class A — window evidence** (has a `[start,end]` range, replayable from a
  watermark): `:focus_segments`, `:browser_segments`, `:content_recent` (all
  panopticon, keyed on `ts`); `:git_commits` (currently the post-commit hook
  feed, *not* panopticon — see ISSUE-006; keyed on `%cI`); `:bough_recent` /
  `:bough_day` (**bough** — a separate note/graph store, keyed by nanoid).
- **Class B — present-tense state** (no range, only the perceive instant, **not
  replayable**): `:current_window` (live `current/sway.json` snapshot),
  `:git_state` (live `git` probe of emacs `cwd`), `:fs_state` (live recent-files
  probe of `cwd`), `:bough_active` (live bough pointer).

Consequence: when perception decouples and the consumer runs late, only class A
survives as honest archaeology; class B is either the wrong era (consume-time
live state) or absent. The codebase already names this seam — `:cue_only`
strips exactly class A and keeps exactly class B. The original delta framing
("an extraction, not a build") understated this: making ADR-001's premise true
is itself the work.

### Drivers / inputs

- ISSUE-001 (budget-gated perception) — fixed at root here.
- ISSUE-006 (git sensor bwrap-blind) — the git half of the signal-model fix
  consolidates *into* ISSUE-006's poller (see §3, deferred).
- ADR-001 (accepted) — this DR builds it and amends its premise.
- ADR-002 (proposed) — the arrival gate; relies on this split + on "sensors
  charge attributes every tick" (drives DEC-probes-perceive-side).
- POL-001 — perception stays in `.emacs.d` (editor-substrate sensing; not a
  daemon extraction).

### Constraints / guardrails

- Parcels immutable + append-only; consumption tracked by a separate cursor,
  never by mutating a parcel (architecture "State: append-only artifacts").
- Idempotency keys on segment `end_ts`, not wall-clock — late/doubled
  invocations re-derive the same frontier.
- The capsule stays **recency-biased**; we explicitly do **not** build a
  backlog-spanning capsule (write amplification, token cost).
- Replay-determinism: any future seeded roll (ADR-002) is out of scope here.

### Out of scope

- The arrival gate / metabolic scheduling (ADR-002 / IMPR-012) — consumer
  trigger stays manual / waybar until it lands.
- `:git_state` promotion to status segments — deferred (cross-repo panopticon
  work; see §3).
- bough-as-of querying — bough is *deprecated from the active path*, not
  re-plumbed.
- Rich memory accrual over the full backlog — the cursor advances the frontier;
  no heavyweight per-segment replay pass is built.

## 3. Architecture Intent

### Target control flow

```
broker-run(name):
  prepare = broker--prepare(mode)          ; alloc run_id, freeze time_now
  prepare = perceive(prepare, mode)        ; UNCONDITIONAL — no LLM, no interventions
  if session-active   → write blocked  (percept already written) ; return
  if budget-exceeded  → write-denied   (percept already written) ; return   ← ISSUE-001 FIXED
  else consume(mode, prepare, dir)         ; effects + tokens + cursor advance + LLM
```

Perception is now structurally upstream of every gate. Both denial paths
receive an already-perceived `prepare`, so they persist `percept.json` for free.

### The perceive / consume boundary

| step | side | rationale |
|---|---|---|
| `percept-build` (evidence → canon) | **perceive** | the sensing; pure over the recency window |
| persist `percept.json` | **perceive** | parcel / audit artifact (D1a); a *recording*, not an *acting*, effect |
| curiosity / content / wpm probes | **perceive** | DEC-probes-perceive-side: deterministic append-only charges; keeps ADR-002 "charge every tick" |
| `observer-process` (outcome accrual) | **consume** | DB writes; runs before motive so the snapshot sees matured `worked_count` |
| `resonance-derive` | **consume** | prompt-prep — only needed when a model runs |
| `motive-read` | **consume** | prompt-prep; ordered after observer |
| `sensor-alerts-check` (fires `notify`) | **consume** | user-visible intervention |
| advance ingest watermark | **consume** | only a real (gated) run advances the consumption frontier |
| `context-fn` → `bundle.json`; `make-process` | **consume** | cognition |

**Side-effect reinterpretation (load-bearing).** ADR-001 says perception is
"side-effect-free." Read literally that is already false (perceive persists
`percept.json`). This DR fixes the definition: perception forbids **acting**
(interventions, user-visible effects) and **cognition** (tokens/LLM); it permits
**deterministic, append-only recordings** (`percept.json`, attribute charges).
ADR-001 is amended to say this.

### Signal-model promotion (class B → class A)

The percept is reshaped to read (almost) only panopticon series:

| was (class B) | becomes |
|---|---|
| `:current_window` (live sway snapshot) | head of the `focus` series — already a panopticon stream; stop reading the live file |
| `:fs_state` (cwd recent files) | dropped (low-value, emacs-cwd-biased) |
| `:bough_active` + `:bough_recent` + `:bough_day` | **deprecated** — retired from the active percept path; query code kept dormant; revisit (incl. storage) if bough use revives |
| `:git_state` (live cwd git) | **deferred** — promotion to registry-driven `git status` segments is ISSUE-006-extended (cross-repo panopticon producer). Stays a live cwd probe in the interim — the one known-residual non-replayable bit |

After this slice, perception reads panopticon series (focus, browser, content,
git-commits) plus the residual live `git_state`. Substrate count drops (bough +
two live probes gone); signal quality rises (env-agnostic, not cwd-biased).

### The carve — what lands now vs deferred

DE-010 cannot *contain* the git producer (panopticon is a separate, ungoverned
repo). Decision: **land the independent `.emacs.d` slice now.**

- **Lands now** (needs nothing from panopticon): perceive-before-gate
  (ISSUE-001), bough retire, `current_window`→focus-head, drop `fs_state`,
  ingest watermark + consume-side advance + backlog depth, the
  perceive/consume split.
- **Deferred follow-up** (depends on the consolidated panopticon git producer —
  ISSUE-006 extended with a repo registry + `git status` segments):
  `:git_state` promotion.

### Cursor / watermark

- Watermark = `end_ts` of the newest segment at consume time, over the
  **monotonic attention sources only** (focus / browser / content). `consume`
  advances it after a successful run; `perceive` never touches it.
- Backlog depth = `head − watermark` — exactly what the future gate (ADR-002)
  and the waybar widget read to decide "summon the heavy consumer now."
- Idempotency: re-deriving "segments with `end_ts ∈ (watermark, head]`" is
  stable across late/doubled invocations.
- Completeness guarantee is **negative**: nothing newer-than-watermark is
  silently skipped. We do *not* build a positive "replay every backlog segment
  into memory" pass — no current consumer needs it (the model's memory tools +
  `observer-process` already accrue per run).
- **The git feed is excluded from the watermark.** Git rows key on `%cI`
  (committer date), which is **backdatable** (rebase/amend) — a commit can land
  with `end_ts < watermark` and would be silently skipped, breaking the negative
  guarantee. Git keeps its existing self-contained 24h look-back window
  (`git-window-minutes`), which is idempotent by construction (re-scan the same
  horizon). Only the monotonic-arrival sources ride the watermark.

### Materialization vs D1=B (no contradiction)

`perceive` persists `percept.json` on **every `broker-run` invocation**,
including budget-denied ones (that *is* the ISSUE-001 fix). This is not the
write-amplification D1=B rejected: D1=A's "~144 mostly-empty parcels/day" came
from a per-tick *perception timer*, and **this delta adds no perception timer**
(§9). Invocation cardinality is unchanged from today (waybar / morning / motd /
manual) plus the newly-covered budget-denied case. So `percept.json` is
materialized per *invocation* (affirmatively resolving D1a — it is the
perception-of-record audit artifact), while the backlog parcel remains a *view*
over the segment log (D1=B). Both hold.

## 7. Design Decisions & Trade-offs

- **DEC-perceive-boundary** — perceive = percept-build + persist + probes;
  consume = observer/resonance/motive/alerts/cursor/LLM. Rationale: perceive is
  exactly the deterministic, unconditional, token-free sensing; everything that
  acts, spends, or only matters when a model runs is consume-side.
- **DEC-class-b-promotion** — promote/drop class B so perception reads
  (near-)only replayable series. Makes ADR-001's premise true; raises signal
  quality; cuts substrate count.
- **DEC-probes-perceive-side** — attribute-charging probes run with perceive
  every tick. Reinterprets ADR-001 "side-effect-free" as "no acting/cognition;
  deterministic recordings allowed." Keeps ADR-002's continuous-integration
  premise intact. Rejected: consume-side probes (irregular charging would
  undermine ADR-002 before acceptance).
- **DEC-cursor-consume-side** — the watermark records the *cognition*
  consumption frontier; perceive's capsule stays recency-windowed. Rejected:
  re-keying the evidence window to the watermark (produces a backlog-spanning
  capsule we do not want).
- **DEC-spec-authority-stays-doc** — perception loop stays doc-canon
  (`perceptual-design.md`, updated here); does not graduate to a SPEC in this
  delta. Revisit if it stabilises.
- **bough deprecation** — retire from the active path, keep code dormant.
  Rationale: denote/org has displaced bough; its only live contribution is a
  "you're not using bough" nag. Reversible.

## 8. Open Questions

- [ ] Residual `:git_state` non-replayability until the panopticon git producer
  (ISSUE-006-extended) lands — accepted as a documented interim residual.
- [ ] Consumer accrual semantics beyond frontier-advance — deliberately minimal
  in this delta; revisit if a consumer needs full-backlog replay.
- [ ] **`current_window` freshness regression.** Reading the head of the `focus`
  series instead of the live `current/sway.json` snapshot makes "what is now"
  staler by up to one segmentize interval. `sensor-alerts-check`'s
  `current-window-stale-seconds` (300s) guard may fire more often. IP must
  re-tune the threshold or source `current_window` freshness deliberately.
- [ ] **MCP recomposition.** `context-interactive` calls `assemble-context` but
  not `observer-process`; after the split it must call perceive + the
  resonance/motive enrichment in the same order to keep its bundle byte-stable
  (VT-mcp-bundle). Confirm no observer dependency leaks into the capsule.

## 9. Rollout & Operational Notes

- **Migration**: no systemd perception timer is re-enabled (D1=B). Consumer
  trigger stays manual / waybar until ADR-002's gate lands. The interim percept
  keeps a live `git_state` so no working-tree signal is lost before the
  panopticon producer ships.
- **Observability**: backlog depth (`head − watermark`) is the new operational
  signal — surface it on the waybar widget.
- **Recovery / rollback**: the cut is internal to broker control flow; reverting
  is restoring perceive into `--spawn` and the budget-denied early return. The
  watermark store is additive (a missing/zero watermark = "consume from head").
