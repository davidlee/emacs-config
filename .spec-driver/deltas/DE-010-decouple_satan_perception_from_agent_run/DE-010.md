## 1. Summary & Context

Split the SATAN tick into **perception** (deterministic, token-free,
side-effect-free) and **cognition** (the LLM run that has effects and spends
budget). Today `dl-satan-broker--prepare` already builds the percept
deterministically (frozen `time_now`, evidence window, canon, resonance,
motive) — then spawns the model as its last step. This delta cuts that seam:
promote `--prepare` to a standalone, scheduled perception entrypoint that
writes durable append-only parcels; make the spawn a separate, slacker-cadence
**consumer** that drains the parcel backlog.

- **Technical Spec(s)**: none yet — SATAN perceptual loop is doc-canon
  (`docs/satan/perceptual-design.md`, `docs/satan/data-collection.md`,
  `docs/satan/architecture.md`), not yet a SPEC. Spec authority may need to
  move; revisit during scoping.
- **Change Drivers**:
  - `ISSUE-001` — every run writes `percept.json`; **budget-denied runs skip
    it**. Perception is gated by LLM quota because it rides inside the spawn
    lifecycle. This delta fixes it structurally.
  - Coupling pain: the systemd tick timer is **disabled** in favour of a waybar
    widget timer, *because* tick = context-prep **+** an LLM with side effects.
    Splitting them dissolves the reason the timer was disabled.

## 2. Motivation

Three wins from the split:

1. **Budget independence.** Perception writes regardless of whether any model
   runs (fixes `ISSUE-001` at the root, not with a patch).
2. **Completeness.** "All segments since watermark" replaces the irregular
   10-min keyhole → contiguous segment-of-record, no gaps/overlaps.
3. **Inspection-as-queue.** Parcels carry processed/unprocessed; the consumer
   drains a backlog under slack limits.

The waybar widget is **promoted, not lost**: from "summon the whole beast" to
"summon the heavy consumer now" — manual override beside the auto gate. Strictly
more control than today.

## 3. Scope & Objectives

Three components — name the middle one or it recollapses to two:

1. **Perceive** — extracted from `broker--prepare`. Scheduled (systemd timer,
   re-enabled; ~10 min as reasonable as 30 once token-free). Deterministic,
   append-only, zero effects, zero tokens. **Exactly one percept builder** — an
   *extraction*, not a parallel implementation.
2. **Consumer** — the existing spawn, now a backlog drainer. Slack/irregular
   cadence, slacker limits, has effects. Recency-biased replay.
3. *(Gate — the arrival trigger — is tracked separately: see §7 / [[IMPR-012]].)*

- **Operational Constraints**:
  - Parcels are **immutable + append-only**; consumption tracked by a
    **separate cursor**, never by mutating the parcel (matches the
    architecture "State: append-only artifacts" doctrine).
  - Parcel boundaries key on **segment offset, not wall-clock** → late/
    overlapping systemd ticks re-derive the same boundary (idempotent).
  - Two retention semantics, not one queue: **intervention relevance**
    (newest-first + freshness horizon) vs **memory/outcome accrual** (all
    parcels, order-independent, complete). Model as one ingest cursor + a
    per-parcel "intervention-eligible-until" stamp.
- **Dependencies**: rides on the panopticon segment-schema contract
  (`ISSUE-006` portable-panopticon work) — the parcel is "segments since
  watermark."

## 4. Out of Scope

- **Arrival gate / metabolic scheduling** — [[IMPR-012]]. The gate is the
  *trigger* component; it depends on this split landing but is its own change
  (and is governance-visible).
- **Fast intervention reflex** (episode-scoped transient attributes) — deferred;
  also tracked under [[IMPR-012]].

## 5. Approach Overview

- **System Touchpoints**: `dl-satan-broker.el` (`--prepare`/`--spawn` seam),
  `dl-satan-tick.el` (timer), `dl-satan-context.el`, `dl-satan-budget.el`,
  the `runs/` artefact dir, panopticon segment log + a new cursor/watermark.
- **Key Changes**:
  - Extract `broker--prepare` → standalone `satan-perceive` entrypoint.
  - Durable append-only parcel + segment-offset watermark + consumption cursor.
  - Consumer = drain unprocessed parcels, reason, emit interventions, advance
    cursor.
- **Migration / Rollout Notes**: re-enable the systemd perception timer once
  perception is provably side-effect-free; keep the waybar widget as the manual
  consumer trigger.

## 6. Verification Strategy

- **Acceptance Criteria** (draft):
  - Perception writes a parcel on a budget-denied tick (`ISSUE-001` regression).
  - Doubled/late timer fire produces no duplicate/corrupt parcel (offset-keyed
    idempotency).
  - Consumer drains backlog and advances the cursor without mutating parcels.

## 7. Follow-ups & Tracking

- **Backlog Items**: [[IMPR-012]] — arrival gate (depends on this split).
- **Open Decisions / Questions** (gate scoping — settle before IP):
  - **D1 — perception: process or function?** (A) materialize `packet-<n>.json`
    every tick (durable, diffable, freezes canon vs grammar drift; write
    amplification) vs (B) virtual — perception is a pure function over the
    already-durable segment log; only the gate needs a timer; **lazy-materialize**
    on gate-fire. *Lean: B + lazy materialization.*
  - **D2 — consumer: pure replayer or hybrid?** Pure replayer (clean, fully
    decoupled, loses real-time reflex → needs a separate cheap reflex path) vs
    hybrid (decoupled perception + a thin cheap touch for latency-sensitive
    cues). *Lean: hybrid, extraction-first.* Worst-case intervention latency
    ≈ perception period + gate + spawn (~10–12 min); acceptable, document the
    floor.
