> **Status: shaped.** DR-010 drafted (2026-06-09). Shape locked: perceive =
> deterministic sensing before the budget gate; consume = the gated LLM run.
> A 2026-06-09 design pass exposed that ADR-001's "pure function over the
> durable segment log" premise was aspirational (the percept fuses replayable
> series with non-replayable present-tense reads + bough) and folded a
> **signal-model promotion (class B → class A)** into scope. No IP/phases yet.

## 1. Summary & Context

Split the SATAN tick into **perception** (deterministic, token-free,
side-effect-free) and **cognition** (the LLM run that has effects and spends
budget). Today `dl-satan-broker--prepare` already builds the percept
deterministically (frozen `time_now`, evidence window, canon, resonance,
motive) — then spawns the model as its last step. This delta cuts that seam:
promote `--prepare` to a standalone, scheduled perception entrypoint that
writes durable append-only parcels; make the spawn a separate, slacker-cadence
**consumer** that drains the parcel backlog.

- **Technical Spec(s)**: none yet — SATAN perceptual loop is doc-canon
  (`docs/satan/perceptual-design.md`, `docs/satan/data-collection.md`,
  `docs/satan/architecture.md`), not yet a SPEC. Spec authority may need to
  move; revisit during scoping.
- **Change Drivers**:
  - `ISSUE-001` — every run writes `percept.json`; **budget-denied runs skip
    it**. Perception is gated by LLM quota because it rides inside the spawn
    lifecycle. This delta fixes it structurally.
  - Coupling pain: the systemd tick timer is **disabled** in favour of a waybar
    widget timer, *because* tick = context-prep **+** an LLM with side effects.
    Splitting them dissolves the reason the timer was disabled.

## 2. Motivation

Three wins from the split:

1. **Budget independence.** Perception writes regardless of whether any model
   runs (fixes `ISSUE-001` at the root, not with a patch).
2. **Completeness.** "All segments since watermark" replaces the irregular
   10-min keyhole → contiguous segment-of-record, no gaps/overlaps.
3. **Inspection-as-queue.** Parcels carry processed/unprocessed; the consumer
   drains a backlog under slack limits.

The waybar widget is **promoted, not lost**: from "summon the whole beast" to
"summon the heavy consumer now" — manual override beside the auto gate. Strictly
more control than today.

## 3. Scope & Objectives

Three components — name the middle one or it recollapses to two:

1. **Perceive** — the deterministic sensing, lifted **before the budget gate**
   in `broker-run` (today it runs inside `broker--spawn`, downstream of the
   gate — the ISSUE-001 root). Builds the percept (recency-windowed capsule),
   persists `percept.json`, runs the attribute-charging probes. No LLM, no
   interventions. **Exactly one percept builder** — an *extraction*, not a
   parallel implementation. Permits deterministic append-only *recordings*
   (`percept.json`, attr charges); forbids *acting* and *cognition*. Under
   D1=B there is **no perception timer in this delta** — perceive is code the
   gates and consumer call.
2. **Consumer** — the existing spawn, now gated cognition: `observer-process`,
   resonance/motive enrichment, sensor-alerts (intervention), advance the
   ingest watermark, build the bundle, spawn the model. Slack/irregular
   cadence; carries all effects.
3. *(Gate — the arrival trigger — is tracked separately: see §7 / [[IMPR-012]].)*

### Signal-model promotion (class B → class A)

A 2026-06-09 pass found the percept is a fan-in over three sequencing
mechanisms, not one segment log. **Class A** (replayable window series:
focus/browser/content panopticon segments, git-commit feed, bough) vs **class B**
(non-replayable present-tense reads: live sway snapshot, live cwd git/fs, live
bough pointer). ADR-001's "pure function over the durable segment log" only
holds for class A. This delta promotes/drops class B so perception reads
(near-)only replayable series:

- `:current_window` → head of the `focus` series (already a panopticon stream).
- `:fs_state` → **dropped** (low-value, emacs-cwd-biased).
- bough (`:bough_active`/`:bough_recent`/`:bough_day`) → **deprecated** from the
  active path; query code kept dormant (denote/org has displaced it).
- `:git_state` → **deferred** (see §4): promotion to registry-driven
  `git status` segments is ISSUE-006-extended (cross-repo panopticon producer).
  Stays a live cwd probe in the interim — the one residual non-replayable bit.

Net: substrate count drops (bough + two live probes gone); signal quality rises
(env-agnostic, not cwd-biased); ADR-001's premise becomes true (modulo the
deferred `git_state` residual).

### Carve — independent slice lands now

The git producer is panopticon (separate, ungoverned repo) — DE-010 cannot
contain it. Decision: **land the independent `.emacs.d` slice now**
(perceive-before-gate, bough retire, `current_window`→focus-head, drop
`fs_state`, ingest watermark + consume-side advance + backlog depth). Defer the
`:git_state` promotion to a follow-up that depends on the panopticon producer.

- **Operational Constraints**:
  - Parcels are **immutable + append-only**; consumption tracked by a
    **separate cursor**, never by mutating the parcel (matches the
    architecture "State: append-only artifacts" doctrine).
  - Parcel boundaries key on **segment offset, not wall-clock** → late/
    overlapping systemd ticks re-derive the same boundary (idempotent).
  - Two retention semantics, not one queue: **intervention relevance**
    (newest-first + freshness horizon) vs **memory/outcome accrual** (all
    parcels, order-independent, complete). Model as one ingest cursor + a
    per-parcel "intervention-eligible-until" stamp.
- **Dependencies**: rides on the panopticon segment-schema contract
  (`ISSUE-006` portable-panopticon work) — the parcel is "segments since
  watermark."

## 4. Out of Scope

- **Arrival gate / metabolic scheduling** — [[IMPR-012]]. The gate is the
  *trigger* component; it depends on this split landing but is its own change
  (and is governance-visible).
- **Fast intervention reflex** (episode-scoped transient attributes) — deferred;
  also tracked under [[IMPR-012]].
- **`:git_state` promotion** — registry-driven `git status` segments. Cross-repo
  panopticon work (ISSUE-006-extended: one host-side producer emits commit *and*
  status segments, fed by a repo registry; poller owns discovery, commit-hook
  upsert is a non-load-bearing fast-path). Deferred follow-up depending on that
  producer. Interim: `git_state` stays a live cwd probe.
- **bough-as-of querying** — bough is *deprecated*, not re-plumbed. If usage
  revives, solve historical querying + storage then.
- **Rich backlog accrual** — the cursor advances the consumption frontier; no
  heavyweight "replay every backlog segment into memory" pass is built (no
  consumer needs it; the model's memory tools + `observer-process` already
  accrue per run). The completeness guarantee is negative: nothing
  newer-than-watermark is silently skipped.

## 5. Approach Overview

- **System Touchpoints**: `dl-satan-broker.el` (`--prepare`/`--spawn` seam),
  `dl-satan-tick.el` (timer), `dl-satan-context.el`, `dl-satan-budget.el`,
  the `runs/` artefact dir, panopticon segment log + a new cursor/watermark.
- **Key Changes**:
  - Lift perceive (percept-build + persist + probes) out of `broker--spawn` to
    **before the budget gate** in `broker-run`; budget-denied + session-blocked
    paths receive an already-perceived `prepare` (ISSUE-001 fixed at root).
  - Split `assemble-context` → `perceive` (percept/sensor_status/probes) and a
    consume-side resonance/motive enrichment; MCP interactive-boot calls both.
  - Promote class B → class A (current_window→focus-head; drop fs_state;
    deprecate bough); `git_state` deferred.
  - Ingest watermark on `end_ts` (consume-side advance); idempotent
    re-derivation; backlog depth = `head − watermark` (drives gate + waybar).
  - Note: the watermark is the *cognition* frontier — the capsule stays
    recency-windowed (no backlog-spanning capsule).
- **Migration / Rollout Notes**: under D1=B, **no systemd perception timer is
  re-enabled in this delta** — perception is on-demand; consumer trigger stays
  manual / waybar widget until the gate ([[IMPR-012]]) lands. The 10-min cadence
  question moves entirely into IMPR-012.

## 6. Verification Strategy

- **Acceptance Criteria** (draft):
  - Perception writes a parcel on a budget-denied tick (`ISSUE-001` regression).
  - Doubled/late timer fire produces no duplicate/corrupt parcel (offset-keyed
    idempotency).
  - Consumer drains backlog and advances the cursor without mutating parcels.

## 7. Follow-ups & Tracking

- **Backlog Items**: [[IMPR-012]] — arrival gate (depends on this split).
- **Follow-up delta**: `:git_state` promotion (registry-driven `git status`
  segments) — depends on the ISSUE-006-extended panopticon git producer.
- **Decisions settled 2026-06-09** (DR-010 design pass):
  - **Perceive/consume boundary** — perceive = percept-build + persist + probes;
    consume = observer/resonance/motive/alerts/cursor/LLM.
  - **Probes → perceive-side** — keeps ADR-002 "charge attributes every tick";
    reinterprets ADR-001 "side-effect-free" as "no acting/cognition;
    deterministic recordings allowed."
  - **Signal model** — class B → class A; bough deprecated; `git_state` deferred.
  - **Cursor** — consume-side cognition frontier; capsule stays recency-windowed.
  - **Spec authority** — perception loop **stays doc-canon**
    (`perceptual-design.md`, updated in this delta); no SPEC graduation here.
  - **ADR-001** — to be **amended**: premise-gap, B→A, bough deprecation,
    side-effect reinterpretation.
- **Pre-IP remaining**: `plan-phases` for an IP.
  - **D1 — perception: process or function? → RESOLVED B (lazy-materialize)**
    (2026-06-08, lead avenue to explore first). Perception is a pure function
    over the already-durable segment log; the parcel is a *view*, materialized
    lazily on consume. No perception process/timer in this delta; cadence is
    IMPR-012's concern. Rejected A (materialize every tick): write amplification
    + 144 mostly-empty parcels/day.
    - *Residual D1a:* lazy materialization drops the per-tick audit artifact
      ("what did SATAN see at 10:00"). Memory/outcome accrual is unaffected
      (it reads the durable segment log directly via the ingest cursor). If an
      explicit perception-of-record is wanted, add an **optional slow archival
      materialization** (decoupled from consume) — defer unless a need appears.
  - **D2 — consumer: pure replayer or hybrid? → RESOLVED hybrid** (2026-06-09).
    Decoupled perception + a thin, cheap, frequent touch for latency-sensitive
    cues; heavy reasoning drains the backlog at slack cadence. Rationale: under
    D1=B there is no perception timer, so the arrival gate is the only periodic
    clock — giving it the cheap latency-touch is **one mechanism, not two**. The
    pure-replayer alternative would force a *separate* reflex path for the same
    job. Worst-case intervention latency ≈ gate + spawn (~10–12 min); acceptable,
    document the floor. Unblocks ADR-002 acceptance gate #2.
