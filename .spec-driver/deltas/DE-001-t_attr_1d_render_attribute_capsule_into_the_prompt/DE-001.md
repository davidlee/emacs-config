## 1. Summary & Context

- **Technical Spec(s)**: none — SATAN has no tech specs yet; behaviour is
  governed by `docs/satan/refactor/` design notes and the attribute
  design-contract (§2 vocabulary, §9 disable-aware). No revision-first gate
  applies (no spec authority to move).
- **Implementation Plan**: [IP-001](./IP-001.md)
- **Change Drivers**: IMPR-003 (attribute capsule render). Discovered during
  scoping: the bar block already shipped in commit `8612667`; this delta closes
  the remaining gap.

## 2. Motivation

T-attr-1d's bar block is **already in `main`** (commit `8612667`):
`dl-satan-attribute-render.el` renders 10-cell bars, wired into the prompt via
`dl-satan-context.el` (`:attributes` snapshot pre-spawn + block emit) and into
`dl-satan-tank.el`. 21 ERT tests. The model already feels its per-attribute
state.

Two gaps remain against the IMPR-003 brief:

1. The **one-line derived "pressure" summary** (brief §4) was never built —
   `grep pressure` across `satan/` and `framing.txt` is empty. Only per-attribute
   bars render; there is no aggregate the model can read at a glance.
2. The block has never been **verified end-to-end against real data**. The data
   blocker cleared 2026-05-30 (global scope now shows real drift: doubt 0.6,
   shame 0.65, metamorphosis 0.49); the render has only ever been exercised by
   unit tests over fixtures.

## 3. Scope & Objectives

- **Primary Outcomes**:
  - A derived **pressure** line renders into the `# Attributes` capsule block,
    aggregating the 8 attributes into a single legible summary.
  - The pressure line is **disable-aware**: suppressed/marked when attribute
    updates are off (no stale values presented as live).
  - **End-to-end verification**: the assembled prompt shows the real `global`
    snapshot (bars + pressure) for a live broker spawn.
- **Operational Constraints**: broker-only, elisp; no daemon RPC (the render
  reads the DB directly via `dl-satan-attribute--query`, `scope = 'global'`).
  No schema or migration change.
- **Dependencies**: none blocking. ISSUE-003 (test-scope leak) already
  remediated; not a gate.

## 4. Out of Scope

- The **bar block itself** — already shipped (commit `8612667`).
- Any **daemon "snapshot attrs" RPC** — the brief proposed one; the landed
  design reads the DB directly. Not reintroduced here.
- **ISSUE-003** test-isolation fix (transaction-per-test / RAII guard) — tracked
  separately; only its data-hygiene symptom touched this delta's verification.
- Outcome→attribute **coupling depth** — the lone outcome row is
  `unknown`/low-confidence; demonstrating richer coupling is future work, not a
  render concern.

## 5. Approach Overview

- **System Touchpoints**:
  - `satan/dl-satan-attribute-render.el` — add pressure derivation + line.
  - `~/notes/satan/system/framing.txt` — header/label key for the pressure line
    if it needs its own framing string.
  - `satan/test/dl-satan-attribute-render-test.el` — pressure unit tests.
  - `satan/dl-satan-tank.el` — surface the pressure line in the ATTRIBUTES
    section for parity (TBC in DR-001).
- **Key Changes**:
  - Pure `dl-satan-attribute-render--pressure SNAPSHOT -> string` derivation
    (exact formula decided in DR-001).
  - Thread the pressure line into `dl-satan-attribute-render-block` under the
    existing updates-enabled gate.
- **Migration / Rollout Notes**: none. Live via `eval-buffer`/restart; no Nix
  rebuild unless a new file is added (none planned).

## 6. Verification Strategy

- **Acceptance Criteria**:
  - Pressure derivation is pure and unit-tested, including: all-low, single-high,
    all-high, and disabled cases.
  - With updates disabled, the block renders the disabled marker and **no**
    pressure value.
  - E2E (VH/VA): a real broker spawn's assembled prompt contains the
    `# Attributes` block with live `global` bars **and** the pressure line,
    matching the DB snapshot at spawn time.
- **Planned Artefacts**: VT (ERT pressure cases) + VA/VH (e2e prompt capture).
