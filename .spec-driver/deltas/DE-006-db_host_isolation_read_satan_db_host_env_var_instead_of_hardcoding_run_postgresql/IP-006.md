## 1. Summary

- **Delta**: DE-006 — DB host isolation
- **Specs Impacted**: none (infrastructure/test-harness change; no spec authority moves)
- **Problems / Issues**: PROB-test-isolation
- **Desired Outcome**: Postgres host resolved once at the `dl-satan-db` chokepoint via an env-seeded dynamic carrier; `just check` (batch) runs DB tests against supabase; `just check-interactive` runs them safely in the live server; production broker untouched.

## 2. Context & Constraints

- **Current Behaviour**: every DB module hardcodes `/run/postgresql` and passes it as the explicit psql `-h`. `SATAN_DB_HOST` is exported but unread → `check-batch` errors on the prod socket; emacsclient path can only skip-all or risk prod.
- **Target Behaviour**: DR-006 — carrier `dl-satan-db-host-override` (seeded `(getenv "SATAN_DB_HOST")`), chokepoint `(or override host)`, batch prod-guard, single `dl-satan-db-test-db-available-p` gate.
- **Dependencies**: supabase test DB reachable at `SATAN_DB_HOST` (`just db-start`, `just db-init`).
- **Constraints**: production broker behaviour unchanged when `SATAN_DB_HOST` absent; single resolution mechanism; module `*-host` defaults stay literal `/run/postgresql`.
